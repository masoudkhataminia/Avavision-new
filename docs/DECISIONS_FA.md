# دفتر تصمیم‌ها

## D-101 — بازنویسی از صفر (2026-10-08)

- **تصمیم:** نسخه‌ی جدید بدون استفاده از کد قبلی (fork اپ Ultralytics) ساخته شد.
- **دلیل:** کد قبلی خطا و باگ زیاد داشت، شمارش را روی کل تصویر انجام می‌داد نه هر خانه، و مجوز AGPL مانع فروش تجاری بود.
- **اثر:** اصول ایمنی پروژه‌ی قبلی (Fail-safe، Gate مدل، یادگیری فقط با تأیید داروساز) حفظ و با تست پیاده شد.

## D-102 — مستقل از مدل

- **تصمیم:** اپ هر مدل Core ML Object Detection را با یک Manifest می‌پذیرد.
- **دلیل:** انتخاب ابزار آموزش (Create ML یا دیگر) تصمیم تجاری/مجوزی است و نباید کد را قفل کند.

## D-103 — هسته‌ی قابل‌تست جدا از اپ

- **تصمیم:** همه‌ی منطق تصمیم در Swift Package `AvaVisionCore` با Foundation است.
- **دلیل:** تست سریع روی هر سیستم (حتی Linux در CI) و جدا بودن ایمنی از رابط کاربری.

## D-104 — پیش‌فرض‌های محافظه‌کارانه

- سه عکس پشت‌سرهم باید دقیقاً یکسان باشند.
- تشخیص زیر ۶۰٪ اطمینان شمرده نمی‌شود و خانه را به Review می‌برد.
- شیء روی مرز خانه‌ها به هیچ خانه‌ای نسبت داده نمی‌شود.
- Layout کالیبره‌نشده اجازه‌ی قبول خودکار نمی‌دهد.
- برچسب ناشناخته‌ی مدل «قرص» حساب می‌شود.

## D-105 — آستانه‌های Release Gate

حداقل ۱۰۰۰ نمونه، ۶۰۰ نمونه‌ی خطادار، ۵۰ نمونه برای هر دارو، دقت شمارش و Precision/Recall هویت ≥ ۹۵٪، False Acceptance ≤ ۰٫۵٪ (منتقل‌شده از تصمیم ۲۰۲۶-۰۷-۲۸ پروژه‌ی قبلی).

## D-106 — عدم ذخیره‌ی عکس

- **تصمیم:** نسخه‌ی اول عکس ذخیره نمی‌کند؛ فقط hash پیکسل‌ها در Audit.
- **دلیل:** برچسب پک ممکن است اطلاعات بیمار داشته باشد. ذخیره‌ی شواهد تصویری بعداً با رمزگذاری و سیاست نگهداری اضافه می‌شود.

## D-107 — زبان
