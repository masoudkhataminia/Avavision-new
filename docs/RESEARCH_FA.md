# خلاصه‌ی تحقیق: تکنولوژی روز (اکتبر ۲۰۲۶)

این خلاصه پایه‌ی تصمیم‌های فنی مغز AvaVision است. منبع‌ها اصلی‌اند؛ مواردی که تأیید نشدند علامت خورده‌اند.

## ۱. شناسایی قرص در مقالات

- **روش برتر:** Metric learning و جستجوی نزدیک‌ترین نمونه.
  - ePillID: ۴٬۹۰۲ نوع قرص؛ ترکیب ArcFace و triplet؛ MAP حدود ۹۶٪ با دو طرف قرص، ۷۶٪ با یک طرف. ([مقاله](https://arxiv.org/abs/2005.14288))
- **داروی جدید بدون آموزش دوباره:**
  - بهترین راه، حافظه‌ی نمونه یا prototype روی یک چشم ثابت است.
  - SimpleCIL نشان داد این روش از روش‌های پیچیده‌ی یادگیری پیوسته بهتر است. ([مقاله](https://arxiv.org/abs/2303.07338))
- **چند نمونه کافی است:** حدود ۵ عکس از هر دارو نقطه‌ی بهینه است. با قرص‌های روی هم، خطا به‌شدت بالا می‌رود. ([مقاله](https://arxiv.org/html/2603.10833))
- **Imprint OCR:** کمک می‌کند (حدود ۵ درصد) ولی شکننده است. فعلاً در مسیر توسعه است.
- **رد کردن قرص ناشناخته:** آستانه‌ی فاصله یک پایه‌ی قوی است و کیفیتش با دقت شناسایی بالا می‌رود. ([مقاله](https://arxiv.org/abs/2110.06207))

## ۲. سیستم‌های تجاری

| سیستم | روش |
|---|---|
| Parata/BD InspectRx | دوربین چندطیفی؛ کتابخانه‌ی تصویر که از پرکردن‌های همان داروخانه ساخته می‌شود؛ سه وضعیت Correct / Incorrect / **Suspect** |
| JVM VIZEN EX | مقایسه‌ی تعداد، شکل و رنگ؛ تنها رقم منتشرشده: ۴٪ خطای مثبت کاذب |
| Omnicell VBM 200F | بررسی اندازه، شکل، رنگ و تعداد هر دوز و عکس هر بلیستر |
| McKesson BlistAssist | فقط عکس برای بررسی از راه دور؛ بدون شناسایی خودکار |
| استرالیا | Webstercare iCHECK فقط پروفایل یا بارکد را بررسی می‌کند؛ **محصول بینایی ماشین برای Webster-pak پیدا نشد** |

**نتیجه:**

- الگوی صنعت همان معماری AvaVision است: نور ثابت، کتابخانه‌ی محلی که یاد می‌گیرد، وضعیت «مشکوک» و تصمیم انسانی.
- بازار استرالیا برای بررسی تصویری Webster-pak خالی به نظر می‌رسد.

## ۳. ابزار اجرا روی Windows (به‌روزرسانی ۲۰۲۶-۱۰-۰۹)

| ابزار | استفاده در AvaVision |
|---|---|
| ONNX Runtime (MIT) | اجرای چشم و مدل تشخیص؛ خودکار سریع‌ترین سخت‌افزار: TensorRT ← CUDA ← DirectML ← NPU ← CPU |
| OpenCV contrib (Apache-2.0) | مارکر ArUco، صاف کردن پک، شمارش دوروشی روز اول |
| Claude (Anthropic) | متخصص زبانی مشورتی: خواندن لیست دارو، توضیح، نظر دوم ([متخصص زبانی](EXPERT_FA.md)) |
| ابزارهای iOS (Vision feature print، instance mask، Core ML) | دیگر استفاده نمی‌شوند؛ نمونه‌ی iOS در شاخه‌ی `archive/ios-prototype` |

**اندازه‌گیری‌شده روی CPU دوهسته‌ای:** DINOv2-S برای ۵۶ قرص ۲٫۳ ثانیه؛ پیدا کردن پک ~۱۵ ms؛ شمارش ۲۸ خانه ~۸۰ ms برای هر فریم. با کارت NVIDIA انتظار می‌رود چشم به ۳۰–۶۰ ms برسد.

## ۴. مدل‌ها و مجوزها

جدول کامل در [راهنمای آموزش](TRAINING_GUIDE_FA.md#قوانین-مجوز) است.

- **انتخاب‌ها:**
  - DINOv2 (Apache-2.0) برای چشم
  - RF-DETR N/S/M (Apache-2.0) برای تشخیص
  - SAM 2.1 / EdgeTAM (Apache-2.0) برای برچسب‌زدن و بررسی دوم

## ۵. داده‌های عمومی برای استفاده‌ی تجاری

| داده | وضعیت |
|---|---|
| NLM C3PI / RxImage (۷٫۳ گیگابایت، قابل دانلود) | **مبهم**: «تحقیق و توسعه» ذکر شده؛ قبل از استفاده تأیید کتبی از NLM لازم است. قرص‌های آمریکایی |
| ePillID، CURE، VAIPE | فقط تحقیقاتی یا بدون مجوز؛ ممنوع |
| MEDISEG | CC BY 4.0؛ **قابل استفاده** با ذکر منبع |
| MIMS استرالیا (۳٬۴۰۰+ تصویر) | اختصاصی؛ باید با MIMS مذاکره شود |

**نتیجه:** دارایی اصلی، داده‌ی خودِ داروخانه است که مغز جمع می‌کند. این داده انحصاری است و رقبا ندارند.

## ۶. مقررات

- **FDA:** راهنمای PCCP برای مدل‌های یادگیرنده (۲۰۲۴، به‌روز ۲۰۲۵) تغییرات خودکار را با «پروتکل تغییر» از پیش تعریف‌شده می‌پذیرد. ([سند](https://www.fda.gov/media/166704/download))
- **TGA:** در بررسی ۲۰۲۵، هوش مصنوعی تطبیقی را اولویت راهنمای آینده اعلام کرد. **هنوز مشخص نیست AvaVision وسیله‌ی پزشکی حساب شود یا نه.** نظر مشاور regulatory لازم است.
- **اثر طراحی:**
  - مغز AvaVision یک «پروتکل تغییر» صریح و قابل‌تست دارد: کالیبراسیون، دفتر اعتماد، spot check و Audit.
  - چشم و مدل فقط با نسخه‌ی ثابت و از طریق Gate عوض می‌شوند.

## موارد تأییدنشده

- بنچمارک DINOv2 روی قرص.
- سرعت DINOv2 روی کارت NVIDIA واقعی (`avavision benchmark`).
- دقت شمارش دوروشی روی پک و نور واقعی (فقط روی تصویر شبیه‌سازی‌شده تست شده).
- وضعیت تجاری C3PI.
- طبقه‌بندی TGA.
