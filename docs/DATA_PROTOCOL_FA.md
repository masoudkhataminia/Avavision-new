# پروتکل جمع‌آوری داده

هدف: ساختن دیتاست آموزش و یک Holdout مستقل که Release Gate را با مدرک واقعی پاس کند.

## حریم خصوصی (اجباری)

- قبل از عکاسی، برچسب بیمار روی پک پوشانده شود یا عکس طوری گرفته شود که برچسب در کادر نباشد.
- نام بیمار، تاریخ تولد، آدرس و شماره‌ی نسخه هرگز در نام فایل یا متادیتا نیاید.
- داده هرگز وارد Git نمی‌شود (`data/` در `.gitignore` است). نگهداری: دیسک رمزگذاری‌شده با دسترسی محدود.
- قبل از Pilot واقعی: سیاست نگهداری و حذف داده و مشاوره‌ی Privacy Act استرالیا.

## ایستگاه

- پایه‌ی ثابت، فاصله‌ی ثابت دوربین، نور یکنواخت و بدون بازتاب مستقیم.
- همان iPhone و همان تنظیمات که در Pilot استفاده می‌شود.
- پس‌زمینه‌ی تیره و مات زیر پک.

## برچسب‌ها (Object Detection)

برای هر شیء داخل پک یک کادر (bounding box) با یکی از این برچسب‌ها:

| برچسب مدل | معنی در Manifest |
|---|---|
| `pill` | قرص/کپسول کامل، بدون ادعای هویت |
| `<medication-code>` مثلاً `metformin-500` | قرص کامل با هویت مشخص (همان کد کاتالوگ اپ) |
| `broken` | تکه یا قرص آسیب‌دیده |
| `foreign` | شیء غیر دارویی |

برای شروع (فاز شمارش) فقط `pill`، `broken` و `foreign` کافی است.

## حجم و ترکیب

| مجموعه | حداقل | توضیح |
|---|---|---|
| آموزش | ۳۰۰ عکس پک کامل | از چند پک و چند روز مختلف |
| Holdout | ۱۰۰۰ خانه | از پک‌هایی که در آموزش نبوده‌اند؛ قبل از آموزش قفل می‌شود |
| خطادار در Holdout | ۶۰۰ خانه | عمداً ساخته‌شده: کم، زیاد، داروی اشتباه، شکسته، خارجی |
| هر دارو (برای هویت) | ۵۰ خانه در Holdout | فقط داروهایی که این حد را دارند هویت می‌گیرند |

## گردش کار

۱. عکس‌ها در `data/incoming/` (بیرون از Git).
۲. داروساز محتوای واقعی هر خانه را تأیید می‌کند → `data/confirmed/`.
۳. عکس مشکل‌دار یا بدون تأیید → `data/quarantine/` با علت.
۴. Holdout قبل از هر آموزشی جدا و نسخه‌بندی می‌شود (`data/holdout/v1/`) و دیگر تغییر نمی‌کند.
۵. برای هر فایل: SHA-256 و وضعیت تأیید در `data/manifests/`.

## داده‌های عمومی

قبل از استفاده از هر دیتاست بیرونی، مجوز آن در [خلاصه‌ی تحقیق](RESEARCH_FA.md#۵-داده‌های-عمومی-برای-استفاده‌ی-تجاری) بررسی شود. ePillID، CURE و VAIPE فقط تحقیقاتی‌اند و استفاده نمی‌شوند. دارایی اصلی، داده‌ی تأییدشده‌ی خود داروخانه است.

## ارزیابی

برای هر خانه‌ی Holdout یک `EvaluationSample` بسازید (انتظار، واقعیت تأییدشده، خروجی سیستم) و:

```bash
swift run avavision evaluate samples.json holdout-v1 > evaluation.json
```

خروجی در `evaluation` داخل Manifest مدل قرار می‌گیرد. جزئیات در [راهنمای مدل](MODEL_GUIDE_FA.md).
